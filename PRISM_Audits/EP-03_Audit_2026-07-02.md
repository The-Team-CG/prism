## EP-03-S02 — Proposal

**Tracker Claim:** To Do, 0%, Owner B. Gated on EP-03-S01 Complete. "Handled by CommercialWorkflowService inside commercial-ops." Five sections (Executive Summary, Event Concept, Service Package Summary, Investment Summary, Payment Schedule). PMCM reviews/finalizes before send. Client can accept or request revision. Revision history stored. Financial data hidden from supplier/coordinator/guest. Conforme unlocked only after acceptance.

**Repo Reality:**
- commercial-ops and CommercialWorkflowService exist (524 lines) but tracker note is factually wrong about their purpose, they implement supplier quote request/management (requestSupplierQuotes, addSupplierQuote, selectSupplierQuote, submitSupplierQuoteByToken, reviseSupplierQuoteByToken), PMCM-to-supplier procurement, not client-facing proposals.
- No Proposal entity anywhere in schema.prisma. No PrismProposal type in packages/types. No investment summary/payment schedule financial model, no accept/revision endpoint, no revision-history table.
- Frontend stub found: ClientProposalTab (apps/client/src/app/components/dashboard/dashboard-tabs.tsx:424-565), wired into the client dashboard's proposal tab. Renders a status hero card, "Approve proposal" and "Request revision" buttons, a proposal package summary card.
- VERIFIED LIVE UX DEFECT: neither button has an onClick handler, purely decorative, no backend endpoint exists for them to call even if wired.
- Does not implement the five specified sections, it's a status/checklist aggregator over existing briefing/billing/floorplan data.
- No proposal-acceptance gate on conforme upload exists in code, uploadConforme (audited in EP-01-S03) is unconditional on inquiry status alone.

**Mismatch:** Modest tracker underclaiming, a wired but non-functional UI shell exists that a strict 0% reading wouldn't expect, but it is far short of "in progress." Tracker's technical note about CommercialWorkflowService is actively misleading for planning, should be corrected before implementation starts. commercial-ops's actual existing endpoints (event-commercial.controller.ts) do have correct role gating via requireCommercialActor, unlike the three-epic auth-gap pattern found elsewhere.
