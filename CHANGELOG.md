### Added

- Event games feel more like a live show. The room screen shows answers coming in ("12 of 30 answered", then "Everyone's in!") and the host's reveal button stands out once everyone has answered (`currentRound.answeredCount`). Results bars grow in with their counts ticking up, and a finished game ends on a podium that builds third, second, then first. On phones, a right answer bursts confetti and counts its points up, and the reveal shows the guest's place, how far they moved and a streak (`roundOutcome.streak`). Bingo says when a line is one call away and lights up the claim button once the marks win (`winPattern` in Bingo's game data). A finished game's final results survive a reload.
- Approved Word Cloud responses now form a spatial cloud on the presenter screen while guests are answering.

- Event games play like a game show. On a guest's phone each round has its own moment: a "You're in" screen before the start, big colour-coded answer tiles they tap once, an "Answer locked in" state, a reveal that says whether they were right, the points and the right answer, and standings between rounds and at the end. Scores show only in games with points. The room screen shows the same lettered tiles, then lights the right answer and how the room answered. Before the first round it shows a large join panel with a QR code, the join link and the PIN; during play a small join card stays in the corner. It also has a countdown ring and round dots, Bingo's latest call and a 1–75 board, the Guess the Picture image uncovering, a Spin the Wheel wheel that spins and lands, a Family Feud board that flips, the average on rating slides, and final standings. Live Trivia questions now end with a 10-second results window, as Presenter Deck slides do. The host's Next round reads Reveal answer or Show results when a results window comes next, and steps into it first. The API sends guests `currentRound.revealedAnswer` and `participant.roundOutcome` only once answers close (right away for solo puzzles and Bingo claims), plus a trivia answer tally. The host state carries `currentRound.options`, `calledNumbers`, `picture` and `wheelOutcomes`, and `GET /events/:eventId/game-sessions/:sessionId/media/:objectId/download-authorization` signs the picture for the room screen. The tiles, wheel and standings are shared in `@prism/ui/event-games`.
- Browser acceptance now covers planning templates, postponement and plan sync, PMCM-to-coordinator run sheets, guest walk-in verification, accreditation and the pre-event risk register on desktop and mobile.
- Coordinators have their own portal at `/coordinator` in the event app. It loads only the coordinator workspace, so the PMCM dashboard no longer reads anything for a coordinator; a coordinator who opens a `/dashboard` link (including older message and notification links) is sent to the same view under `/coordinator`, and sign-in lands there. Notification and conversation links for coordinators now point at `/coordinator`. `check:boundaries` gains a rule that keeps PMCM-only event features out of `app/(coordinator)` and `features/coordinators`; only the shared event-day features (live ops, games, registration, messages, account, notices and the PMCM kit) may be imported.
- PMCM can do four things that only had an API before. Issue an addendum from the event's Changes tab (Addenda › Issue addendum): a side panel for what the client signs and what it costs, showing the contract total before and after; the client then signs it and PMCM countersigns. Update a compliance risk on Closure › Compliance (status, owner, mitigation and why). Log a quote a supplier gave by phone or email from Suppliers › Waiting for quotes, so it joins the comparison. Edit, turn off and turn back on a workspace rule in Settings › Event rules. The api-client gains `commercial.addSupplierQuote` and `compliance.updateRisk`/`updateRule`. Browser acceptance covers each, plus venue shortlists, client-owned suppliers and the client notification inbox.
- Browser acceptance drives twelve more handoffs between portals through the real UI: messages, client-reported payments verified on the finance desk, file requirements rejected and replaced, supplier contracts, schedules, deliverables and payout confirmation, scope changes, venue options, venue visits, client floor plan review, coordinator issues resolved in live ops, live-poll games joined by PIN, guest feedback and client testimonials moderated, and privacy requests. Each starts from an event that `scripts/e2e/browser/journey-fixtures.mjs` prepares through the API; the browser README lists what each covers and what is still prepared through the API.
- Coordinators run games during an event. An assigned coordinator can set up, publish, run and moderate games with the same Set up, Run live and Results tabs PMCM uses. Lobby branding and response review stay PMCM-only, and a declined assignment loses game access.
- On phones, the client, supplier, PMCM and coordinator workspaces have a bottom tab bar. More holds every other page, grouped as in the sidebar; search, messages and notifications sit in the top bar, and the account menu is behind the avatar. Inside an event, the client's event switch also leads Home. Tablets and desktop keep the sidebar.

The coordinator must be tagged for the new role and not already hold it on the event; the acknowledgement and attendance stay, the change is audited, and the coordinator is told. It is also how an assignment saved with a role from before the role catalog gets one, so that coordinator can log tasks again.
- Every active event game (live trivia, bingo, guess the picture, spin the wheel, this or that, family feud, split the room, live poll, word cloud, open Q and A, presenter deck) has a large-screen presenter view. PMCM and coordinators open it from the Games tab (Open presenter view); it shows the prompt, a countdown, the join link, QR code and PIN, participant count, and the current round's results. Results and approved answers appear only when a round is paused; pending moderation is never shown. Solo games have no shared session and no presenter view. The host state now includes approved answers for moderated games while paused.
- New Presenter Deck event game (`presenter-deck`, Mentimeter-style): PMCM builds a timed deck of choice, rating-scale (1 to 5 or 1 to 10) and word-cloud prompts. Guests answer on their phones. After each prompt's timer, its totals or approved word-cloud answers show automatically for 10 seconds (answers are closed meanwhile), then the next prompt starts; the host can still pause, resume and advance. Round state carries `resultsOpen`. Word-cloud answers are approved as they are sent and appear live on the presenter screen and for guests, so they no longer wait in the moderation queue; the host can still hide one. Fixed Next round, which was refused for every session because the round check compared start and pause times at different precision. No points are scored. No migration; the new kind is a shared Zod contract in `@prism/types`.
- Legacy data is migrated and its compatibility code removed. Apply the migrations `20261128090000_event-lifecycle_inquiry_client_type_private`, `20261128091000_event-lifecycle_decision_new_event_date` and `20261128092000_operations_coordinator_assignment_role` before deploying the API. ### Changed

- Payment receipt routes are defined once in `@prism/types` (`paymentReceiptRoutes`, ADR-0011). The API mounts them with `@Endpoint`, PMCM calls them through `createPmcmClient` (`pmcmApi` in the event portal), and every answer is parsed against its response schema, failing with `PrismContractError` on a mismatch. The hand-written receipt methods on `createEventOpsClient` are removed, and `PrismPaymentReceipt` and `PrismPaymentAllocationTarget` are now inferred from their schemas.
- The phone bars look and read the same in every portal. One icon stands for one idea everywhere (`@prism/ui/nav-icons`): Events, Calendar, Planning, Tasks, Run sheet, Billing, Messages and Files no longer change icon between client, supplier, PMCM and coordinator, and no two tabs in a bar look alike. Each portal's nav test fails if an item drifts (`navIconDrift`, `phoneBarIconClashes`). Where the top bar already names the page, a phone no longer repeats the name as a heading under it (it stays for screen readers). The supplier's phone Refresh moves from the top bar to the Today page, beside "Updated", as PMCM and coordinators have it. More drops its heading when it holds one group.
- P.R.I.S.M. has a new mark: three blades close around a prism-shaped opening, in one PMCM spectrum (orange to blue). `PrismBrandLogo` draws it from `packages/ui/assets/images/prism-mark.svg` without the white tile, replacing `prism-logo.png`. Every portal now has a favicon (`icon.svg`, a wider-gap cut for small sizes) and a home-screen icon (`apple-icon.png`).
- The PMCM portal is redesigned so each screen leads with what needs PMCM. The Inbox opens on the event that is on today (or the next one), without count tiles, and folds Needs action after five rows. Inquiries is a funnel with counts and how long each new inquiry has waited. ### Removed

- `@prism/api-client` methods no longer take an actor argument, and `EventOpsActorQuery`, `actorPath` and `prismEventOpsActorSchema` are gone. The API has always derived the caller from the verified session token and ignored the `actorRole`/`actorName` query these sent. `events.list` and `clientWorkspace.detail` now take the cursor as their only argument.
- API routes that newer ones replaced are removed: the event document routes under `/events/:eventId/documents` (use `/storage/objects`), the flat `GET /suppliers` list (use `GET /suppliers/directory`), `POST /notifications/:notificationId/acknowledge` (use `POST /notification-inbox/:deliveryId/acknowledgment`) and `PATCH /events/:eventId/coordinators/:assignmentId/replace` (use the `POST` on the same path, which also writes the event-day log). The client and supplier document hubs that no page rendered and the unused `events.documents`, `requestDocumentUpload`, `confirmDocumentUpload` and `documentDownloadAuthorization` methods of `@prism/api-client` are removed with them.
- PMCM routes that repeated other screens are gone from the route registries: Team's roles, assignments, workload and departments views (they showed the roster) and Suppliers' contracts and payments views. `/dashboard/tasks`, which rendered the Inbox again, has no page; it and the old Team views still redirect, Supplier contracts redirect to Events and payments to Finance, and a client's `/events` view redirects to its History. Settings' Signed in as and Default workspace cards and Audit's sessions and privacy panels are gone.
- The snapshot query for an event floor plan is validated by a shared Zod schema in `@prism/types` like every other API input; the API no longer runs class-validator, and its global validation pipe is removed.
- Portals read the API address only from `NEXT_PUBLIC_API_URL`, which must be set (empty means same-origin); `NEXT_PUBLIC_PRISM_API_BASE_URL` is gone, and a missing origin now fails with a clear error instead of falling back to localhost.
- The portal shells no longer accept the unused `eyebrow` prop; the page title alone names the page, and its copy is removed from the portal route models.
- Sample API routes and browser-local demo fallbacks.
- Unused API ports, DTOs, portal primitives, dependencies and UI exports.
- `uat/PRISM-UAT-Form.xlsx`, replaced by the Google Form.
