## [Unreleased]

### Added
- Test-clock pinning guard: `check-test-clock-pinning.mjs` fails when a test compares a hardcoded date against a live clock without `vi.useFakeTimers`, with a reviewed allowlist carrying a written reason per file. Wired into CI.
- Data-invariant verification gate: `apps/api/prisma/data-invariants.json` declares read-only violation queries for audit-chain rootedness, hashing, orphans and forks, billing sequence coverage, and migration-ledger completeness. `check-data-invariants.mjs` runs them with a SELECT-only guard, `--dry-run`, and `--json`; CI runs the dry-run and unit tests, and live mode is intended for a restored snapshot before deploy.
- Deployment secrets runbook covering every repository secret and variable the deploy path requires, after discovering that Deploy has never succeeded.
- Duplicate migration timestamp detection in the Prisma migration guard. Prisma orders migrations lexicographically, so colliding 14-digit versions let the change slug decide apply order; the five historical collisions are grandfathered by policy and any new one fails.
- Prisma migration guardrails: a machine-readable owner/schema policy with normalized legacy SQL checksums, future owner-aware naming and SQL metadata, static order/ownership/kind/risk checks, fail-closed handling for unsupported procedural SQL, CI wiring, and a database migration deployment/drift-recovery runbook. Existing applied migration directories remain unchanged.
- Parallel-worktree tooling: `npm run ports` reports the ports a checkout owns, and `worktree:create`, `worktree:setup`, and `worktree:remove` add, prepare, and tear down linked worktrees. Setup writes that worktree's `PORT`, `CORS_ORIGIN`, and `NEXT_PUBLIC_API_URL`; teardown unlinks `node_modules` junctions before deleting so the primary checkout's dependency tree survives.
- Worktree tooling now proves port ownership, assigns collision-free derived port slots, validates real-path containment, and resolves launcher URLs from the active checkout.
- Worktree hardening now persists collision-free slots in Git metadata, requires durable process leases, rejects reparse-point roots, defaults env seeding to examples, and blocks Docker mode from linked worktrees.
- Launch and shutdown guards now resolve the active checkout's API and portal URLs, filter stale Git worktrees, and remove leases only when their exact wrapper identity still owns the marker.
- PARE dispatch hardening: worker execution receives an abort signal, tracks active executions through shutdown, restores idempotent `pare_triggered` activity auditing, and rejects approval recovery when audit payloads or dispatch ownership do not match the source request.
- Durable supplier-withdrawal PARE dispatches: commercial withdrawal and its audit now enqueue a dedicated `platform_ops.pare_dispatches` row in the same transaction, with lease-token delivery, bounded execution/retry, terminal configuration and source-state failure, and dispatch-keyed PARE approval idempotency. Live PARE remains gated by its existing execution policy.
- Read-model collection limits across role dashboards, inboxes, workspaces, billing, supplier history, live ops, guest feedback/check-ins, and staffing acknowledgements. Stable ID tie-breakers and exact aggregate count queries keep capped windows deterministic without changing response shapes; pagination remains a future contract.
- Centralized transactional command receipts: `WorkflowCommandService` now persists actor- and event-scoped idempotency keys and projected results for commands that supply an explicit payload hash, replays completed commands after authorization, rejects changed hashes, and records the new `trust_ops.command_receipts` table. Existing domain-specific idempotency paths remain in place until each caller supplies a safe hash.
- Editor-time architecture linting for role-portal imports, private API context imports, local shared-contract redefinitions, and inline Zod schemas, with focused boundary tests and a root `lint:architecture` command.
- Guest dashboard polling now checks a lightweight event watermark and refetches the full event payload only when event-visible state changes.
- Root build and typecheck now fail early when the gitignored `@prism/types` output is missing or older than its source, with a direct rebuild command in the error.

### Fixed
- `GET /api/sample/state` required no session. It was deliberately unguarded on the reasoning that it is disabled in production, but that only protects production: staging is shared and not `NODE_ENV=production`, and the aggregate returns the full user directory plus every supplier quote request's `accessToken` - which is the entire authorization for `GET/POST/PATCH /quote-requests/:token`, so an anonymous read yielded working credentials for submitting and revising supplier quotes. The route now requires a verified PmcmAdmin/System session, with an explicit, logged, non-production local opt-in.
- Four test suites compared hardcoded dates against a live clock and would have gone red on the calendar alone, exactly as the guest feedback window already did. They now pin the clock.
- `app.module.test.ts` failed in the full suite and passed in isolation. Nest's preview bootstrap left an internal barrier promise pending for this module graph; the test now scans the graph directly. Verified by fault injection that it still catches the `UnknownExportException` boot failure it was written for.
- Audit-chain integrity outage: `trust_ops.audit_logs.immutable_hash` carried a `DEFAULT ''` since the column was introduced, so the sample seeder's direct `opsAuditLog.create` wrote an unhashed, unlinked row. That row became a second chain root and made every authenticated append fail closed, blocking all sign-in. The repair migration removes rows that were never hash-linked and drops the default, the seeder now appends through `AuditService`, and a regression test reproduces the exact two-root shape.
- Audit integrity incidents are now recorded for every classification. A `broken_chain` previously rethrew before any incident was written, so the most severe state produced the least evidence; security alerts are not chain-linked, so the incident write stays available exactly when the chain does not.
- `orderLinkedAuditLogs` now reports `breakReason` (`multiple_roots`, `fork`, `duplicate_hash`, `disconnected`). An extra chain root was previously reported as a broken hash link, which pointed a live incident investigation at the wrong rows.
- Whether an unverifiable audit chain blocks authentication is now a deliberate posture. `AUTH_AUDIT_INTEGRITY_POSTURE` defaults to `fail_closed`; `degraded` lets an operator restore access to investigate without editing audit rows, and always records the critical incident.
- Billing statement numbering no longer assumes a hardcoded starting sequence. `billing_statement_sequences` is backfilled from existing statement numbers and the allocator derives the next number from real data, so a year with zero or several prior statements no longer skips a number or violates the unique index.
- Guest feedback-window tests pinned their clock, fixing two suites that passed only until the hardcoded fixture date fell outside the seven-day window.
- W51 shared UX acceptance slice: client action-center failure states no longer infer urgency from browser-clock workspace fallbacks; persisted client and supplier action/readiness items now use stable severity/date/id ordering, and supplier readiness explicitly reports unavailable data. Added deterministic action presentation regression coverage. Runtime browser and screen-reader acceptance remains unavailable without the local stack.
- W51 actor action centers: PMCM now composes persisted command-inbox and defense-readiness next actions, guests see only check-in and moderated-feedback next steps, and all added action surfaces include deterministic ordering, explicit unavailable states, visible keyboard focus, and accessible control names. No role receives another actor's private data.
- W25 cancellation/postponement core: shared decision contract, durable actor/reason/timestamp/prior-state records, serializable event state transitions, explicit deposit/fee treatment, coordinator release and supplier obligation impact, retained reschedule history, audited notification/storage intent, and client-visible event status states. External refunds, supplier acceptance, provider delivery and document bytes remain residual W14/W16/W11/W10 scope.
- W26 freeze/addenda and scope-change impact ledger: PMCM can freeze an event, request and decide audited exceptions, and issue monotonic immutable scanned-document addenda. Canonical contract/quote snapshots are compared deterministically; explicit financial deltas update the approved billing source and selected supplier quote deltas are recorded as immutable impact rows. Document bytes remain pending W10 storage and no e-signature is implied; external notifications remain outside this slice under W11.
- Closure and live-ops corrections: explicit reassignment decisions remain authoritative with compare-and-set claiming, wrap-up reminders scan only existing bounded pending records, and PMCM-recorded acknowledgement attribution is distinct from client acknowledgement. Compatibility conforme fixtures now provide confirmed W10 storage objects.
