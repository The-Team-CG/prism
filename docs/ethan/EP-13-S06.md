## Acceptance Criteria

| AC | Requirement |
|----|-------------|
| AC1 | QR code generated per event, links to guest-accessible page, displayable on LED wall |
| AC2 | Guest scans with own camera, no app/account required |
| AC3 | HTTPS-only |
| AC4 | Event info displayed without authentication |
| AC5 | No internal PMCM/coordinator/supplier/billing data exposed |

## Architecture Decision

**Not blocked by PA-63/PA-66.** S06 uses a static QR image encoding a URL opened by the guest's native camera/OS QR reader. No in-app camera scanning code is needed on PRISM's side.

## Implementation Steps

### Step 1 — Install QR dependency

Add `qrcode.react` to `apps/guest/package.json`. This is the only new package required.

### Step 2 — Create info page route

**New file:** `apps/guest/src/app/info/[accessCode]/page.tsx`

- `"use client"` page (matches all other guest pages)
- Dynamic route: `/info/[accessCode]`
- Fetches via `GET /api/guest/events/${accessCode}` using the same `request()` pattern from `/open/page.tsx`
- No session storage, no consent gate, no auth — purely public read-only

**URL structure:** `${NEXT_PUBLIC_GUEST_URL}/info/AYALA-TECH-YALA`
The QR code on the LED wall encodes this URL. Guest's native camera opens it directly.

### Step 3 — Page layout and structure

Mirror the dashboard event details section, stripped down to public-safe fields only.

#### Header section
Dark gradient banner (matching dashboard):
- Eyebrow: "Event information"
- Title: `{eventName}`
- Subtitle: guest-safe description
- Attendance stat: `{attendanceCount} guest(s) checked in`

#### Info grid
Using `border-l` info rows (matching dashboard lines 504--530):

```
[Event]     [{eventName}]
[Date]      [{eventDate}]
[Client]    [{clientName}]
[Readiness] [{readiness with _ replaced by spaces}]
[Floorplan] [{floorPlanStatus with _ replaced by spaces}]
```

#### QR code display
Self-referencing QR code rendered via `qrcode.react` pointing back to the page URL. Convenience feature for cases where the page is projected on the LED wall and someone wants to scan from another device.

**Fields NOT displayed (per AC5):**
- `guestAccessCode` — the QR itself is the code, no need to echo it
- `activeFloorPlanDraftId` — internal
- `id` — internal event ID

### Step 4 — Error handling

- **Invalid/unknown access code:** Friendly "Event not found" page mirroring `not-found.tsx` pattern
- **API offline:** Same `API_OFFLINE_MESSAGE` pattern from dashboard
- **Loading state:** Skeleton matching the page layout

### Step 5 — Styling

- Reuse exact CSS patterns from dashboard:
  - `border-l border-{color} bg-background/60 px-3 py-2.5` for info rows
  - `text-xs font-bold text-muted-foreground` for labels
  - `text-sm font-black text-foreground` for values
  - `bg-[linear-gradient(135deg,#171216,#251222_48%,#10242b)]` for header banner
- No navigation shell — standalone public page
- Responsive: mobile-first (primary target), scales to LED wall
- No eyebrow pills, no active underline treatments, no badge labels (per AGENTS.md visual rules)
