# MS-01: Portal Acceptance Notes

**Source:** Agile calendar line 299 — portal boundaries for Ethan's surfaces
**Owner:** Ethan
**Date:** 2026-06-20

---

## Rules

Every portal surface must pass these checks before it can be marked Sprint-complete. A single failure blocks acceptance.

1. **No PMCM-only data** in any portal response or UI.
2. **No official floorplan editing** from client portal.
3. **Supplier sees only assigned/application-scoped records.**
4. **Guest stays access-code scoped** — no cross-event data, no account persistence.

---

## 1. Supplier Portal

### Must pass

| Check | What to verify | How to test |
|---|---|---|
| Assigned-scope only | Supplier sees only their own quote requests, assignments, and readiness records | Log in as supplier A; confirm no data from supplier B appears in any API response or UI panel. |
| No cross-supplier bids | Supplier cannot read another supplier's confidential quote amounts, terms, or inclusions | Check quote request detail view and API response for `quote-requests/:id` — must reject if not owned. |
| No PMCM private data | No PMCM internal ratings, private review notes, tier-change reasons, or audit logs | Inspect all `/api/supplier/*` response bodies for fields named `internal`, `private`, `rating`, `pmcmNote`, `audit`, `review`. |
| No client-private data | No client billing milestones, conformes, briefing/proposal content, or other client-scoped fields | Check supplier dashboard and readiness board API responses. |
| Event-day status scoped | Supplier can only update status for their own assignments | Attempt `POST /api/supplier/assignments/:id/event-status` with another supplier's assignment ID — must return 403/404. |
| Quote lock enforced | After PMCM locks a quote request, supplier cannot submit or revise | Attempt `POST /api/supplier/quote-requests/:id/submit` on a locked request — must reject. |

### Must NOT do

- Read from `/api/sample/state` as a normal data path (compatibility-only for seed/demo)
- Show PMCM workspace fields (finance, coordinator internals, compliance overrides, audit logs)
- Expose other suppliers' names, ratings, or assignment history

## 2. Guest Portal

### Must pass

| Check | What to verify | How to test |
|---|---|---|
| Event-code scoped | Guest sees data only for the event tied to their access code | Enter code for event A; confirm no references to event B appear in any response or UI. |
| No cross-event navigation | Guest cannot switch events without a new code/flow | There should be no "switch event" or event selector UI. Only "Leave" → `/open`. |
| Consent required | Check-in and feedback writes fail without explicit consent flag | Attempt `POST /api/guest/events/:code/check-ins` without `consent: true` — must reject. |
| Feedback moderated | Guest feedback enters moderation queue, never auto-publishes | Verify `POST /api/guest/events/:code/feedback` response includes a moderation-pending status and does not appear in any public view. |
| No account persistence | Session is cleared on "Leave event" or tab close; no persistent login | Close browser, reopen `/dashboard` — must redirect to `/open` without a valid access code session. |
| No PMCM data | Guest cannot see event cost, internal status, supplier roster, or PMCM workspace data | Inspect all `/api/guest/*` response bodies for PMCM-only fields. |
| No client data | Guest cannot see client contact info, billing data, conformes, or other client-portal fields | Check guest dashboard and check-in API responses. |

### Must NOT do

- Show a sign-in form (guests use code access, not passwords)
- Expose event cost, billing, supplier details, or internal PMCM status
- Allow QR scanning until HTTPS, camera permissions, consent, moderation, and masterlist contracts are ready
- Allow browsing across events or accessing archived event data

## 3. Client Portal (Boundary Checks)

Although Client Action Center DRI is Francis, Ethan owns portal boundary enforcement. These checks apply to `apps/client`.

### Must pass

| Check | What to verify | How to test |
|---|---|---|
| No official floorplan editing | Client cannot create, edit, delete, or publish official floorplan snapshots | Attempt all `POST/PUT/DELETE` on `/api/client/events/:eventId/floorplan/official` — must return 403. Client can only submit preferences and comment on submitted official layouts. |
| Read-only official layouts | Official floorplan views are snapshot-only; no drag, resize, or edit controls | Confirm the canvas/editor UI is not present in client portal for official layouts. |
| No PMCM-only data | Client cannot see internal event costs, supplier private reviews, coordinator internals, compliance overrides, audit logs, or PMCM action queues | Inspect all `/api/client/*` response bodies for PMCM-only fields. Check each dashboard section. |
| Conforme-gated | No dashboard access without a signed conforme on the event | Attempt to access `/dashboard/events/:eventId` for an event without conforme — must redirect or show locked state. |
| Approval authority enforced | Only primary contact can submit approvals | Attempt approval action as a non-primary-contact client user — must reject. |

### Must NOT do

- Show PMCM command inbox, event workspace tabs intended for PMCM only, or internal action queues
- Allow editing of payment records, supplier assignments, or coordinator data
- Expose other clients' event data or cross-client navigation

## 4. Common Acceptance Gates (All Portals)

| Gate | How to enforce |
|---|---|
| No broad sample state | `npm run check:boundaries` must pass. No new `POST /api/sample/state` or `GET /api/sample/state` calls in portal code. |
| No magic storage keys | Session storage keys must import from `@prism/types`, not literal `prism:*` strings. |
| No cross-app imports | Portal apps must not import from other portal apps (e.g., `apps/client` cannot import from `apps/supplier`). |
| DES-01 state language | Status badges use only: Pending, Awaiting Your Action, In Progress, Confirmed, Completed, Cancelled, Locked, Escalated. |
| DES-01 loading states | All data screens have skeleton screens (not spinners on content areas). Spinners allowed on CTA buttons only. |
| DES-01 empty states | Every list/table/data region shows a message + single suggested action when empty. Never a blank box. |
| DES-01 error states | Errors show what went wrong + what the user can do next. Never raw error codes. |
| DES-01 banned patterns | No tables with >5 columns on mobile, no nested modals, no inline editing on list rows, no unlabeled icon-only buttons, no color as sole status indicator, no horizontal scroll on mobile. |
