## Acceptance Criteria

| AC | Requirement |
|----|-------------|
| AC1 | Public form accessible without authentication at `/apply` |
| AC2 | Form captures: company profile, past events portfolio, service category, certifications, price range, contact details, BNI Member toggle |
| AC3 | Submission creates a supplier application record in the database |
| AC4 | PMCM can view and act on submitted applications (inbox is EP-07-S09, separate story) |
| AC5 | Confirmation displayed to applicant after successful submission |
| AC6 | Duplicate submission handling (same email within 14-day window) |
| AC7 | Privacy consent required before submission |

## Architecture Decision

Follow the **public inquiry pattern** (`EP-01-S01`): anonymous `POST` endpoint with no auth, multi-step wizard frontend, Prisma model for storage. The PMCM inbox (`EP-07-S09`) is a separate story — S06 focuses on the public form and API submission only.

**PA-74** (canonical FR number for New-SUP3/New-EX1/New-S1) is a documentation question. Recommend collapsing to `New-SUP3` as primary. Does not block code.

### Step 1 — Prisma Schema: `OpsSupplierApplication`

**File:** `apps/api/prisma/schema.prisma` (add after `OpsSupplier` model)

```prisma
model OpsSupplierApplication {
  id                String   @id
  companyName       String   @map("company_name")
  contactName       String   @map("contact_name")
  email             String
  normalizedEmail   String   @default("") @map("normalized_email")
  phone             String   @default("")
  categoryId        String?  @map("category_id")
  pastEvents        String   @default("") @map("past_events")
  serviceInclusions String   @default("") @map("service_inclusions")
  certifications    String   @default("")
  priceRange        String   @default("") @map("price_range")
  bniMember         Boolean  @default(false) @map("bni_member")
  portfolioUrl      String   @default("") @map("portfolio_url")
  additionalNotes   String   @default("") @map("additional_notes")
  status            String   @default("pending")
  declineReason     String?  @map("decline_reason")
  reviewedAt        DateTime? @map("reviewed_at")
  approvedAt        DateTime? @map("approved_at")
  privacyConsentAccepted   Boolean  @default(false) @map("privacy_consent_accepted")
  privacyNoticeVersion     String   @default("") @map("privacy_notice_version")
  createdAt         DateTime @default(now()) @map("created_at")
  updatedAt         DateTime @default(now()) @updatedAt @map("updated_at")

  category OpsSupplierCategory? @relation(fields: [categoryId], references: [id], onDelete: SetNull)

  @@schema("supplier_ops")
}
```

### Step 4 — API Service: `createSupplierApplication()`

**File:** `apps/api/libs/modules/supplier-ops/src/services/suppliers.service.ts` (add method)

Follow `InquiriesService.createInquiry()` pattern:
1. Validate `privacyConsentAccepted === true`
2. Normalize email
3. Check for duplicate applications within 14-day window on same email
4. Create record with `id: \`sap_${randomUUID()}\``
5. Set `status: 'pending'`
6. Return mapped application

### Step 10 — Supplier Portal: `/apply` Page

**New file:** `apps/supplier/src/app/apply/page.tsx`

Multi-step wizard following `PublicInquiryPage.tsx` pattern:

#### Form Steps

**Step 1 — Company Info**
- Company Name (required)
- Contact Name (required)
- Email (required)
- Phone (optional)
- BNI Member toggle (optional)

**Step 2 — Services & Portfolio**
- Service Category (required) — select from `OpsSupplierCategory` list
- Past Events Portfolio (textarea, optional)
- Service Inclusions (textarea, optional)
- Price Range (select, optional)

**Step 3 — Certifications & Additional**
- Certifications (textarea, optional)
- Portfolio URL (input, optional)
- Additional Notes (textarea, optional)

**Step 4 — Confirm & Submit**
- Summary of all entered fields
- Privacy consent checkbox (required)
- Submit button

#### Validation
```typescript
function canContinue(step: number) {
  if (step === 0) return Boolean(form.companyName && form.contactName && form.email);
  if (step === 1) return Boolean(form.categoryId);
  return form.privacyConsentAccepted; // step 2 and 3
}
```

#### Layout
- Full-page split: Left aside panel (branding + trust signals) + right form panel
- Same `lg:grid-cols-[452px_minmax(0,1fr)]` grid as inquiry form
- Gradient background with grid overlay
- Stepper component with numbered circles
- Footer bar with Back/Continue/Submit buttons

#### Submission Flow
1. Build payload from form state
2. Call `prismApi.createSupplierApplication(payload)`
3. On success: show confirmation screen with reference ID
4. On failure: show `<Alert variant="destructive">` with error message

#### Loading Categories
Fetch `GET /suppliers/categories` on mount to populate the service category dropdown. This endpoint already exists in `supplier-directory.controller.ts`.
