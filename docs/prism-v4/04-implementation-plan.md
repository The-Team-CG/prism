# P.R.I.S.M Version 4 Implementation Plan

This plan converts each source catalog row into implementation work. Rows are source-preserving, so cross-persona or AI-governance rows may appear where the original catalog repeats them. The official count summary remains the source of truth for manuscript totals.

Current implementation status is tracked separately in `07-implemented-feature-revisions.md`. Check that file before adding new feature scope: many catalog rows already have partial code paths that should be revised instead of rebuilt from scratch.

## Build Order
| Order | Slice | Scope |
| --- | --- | --- |
| 1 | Platform and security baseline | Auth, roles, sessions, audit trail, secure uploads, privacy notice, data anonymization, notification channels. |
| 2 | Prism defense workflow | Public inquiry to PMCM admin acceptance, conforme gate, event workspace, file hub, supplier quote, CE, proposal, client approval, billing, floor plan, coordinator assignment, guest registration, archive. |
| 3 | Portal hardening | Client, supplier, coordinator, and guest portal polish, permissions, notifications, and mobile views. |
| 4 | Operational depth | Risk, permits, multi-day support, accreditation, contract fallback paths, payment variations, post-event insight capture. |
| 5 | AI rollout | Only after `FR-AI-ZDR`, `DataSanitizer`, `AIAuditLog`, and human approval gates are working. |
| 6 | Phase 2+ roadmap | Advanced venue library, presets, engagement games, analytics, package recommendations, and external marketing simulations. |

## Current Revision Gate

Before implementing a new catalog row, run this gate:

| Gate | Required check |
| --- | --- |
| Scope source | Confirm the row exists in `01-complete-feature-catalog.md` and identify its FR number. |
| Current status | Check `07-implemented-feature-revisions.md` for existing UI/API/schema coverage and known gaps. |
| App boundary | Keep PMCM command work in `prism-event`, client work in `prism-client`, supplier work in `prism-supplier`, guest work in `prism-guest`, and shared backend work in `prism-api`. |
| Revision first | If the feature is already partial, finish the revision path before creating a parallel mockup. |
| Security | For dashboards and event data, add or preserve API actor/role checks. Public surfaces remain landing and inquiry only. |
| Floorplan ownership | PMCM owns official layouts in `prism-event`; client users submit preferences and review approved/submitted official layouts read-only. |
| Verification | Add or run focused backend/frontend checks listed in `07-implemented-feature-revisions.md`. |
